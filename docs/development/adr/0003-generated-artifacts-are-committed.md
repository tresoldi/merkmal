# 0003. Generated C tables and the WebAssembly build are committed

## Context

The compiled-in data (`src/generated/*.c`) is generated by Python from
`data/models/`, `data/geometries/` and `data/diacritics/`, and the browser demo
(`web/merkmal.js`, `web/merkmal.wasm`) by Emscripten. The house standard does
not commit cheap, deterministic artifacts unless doing so materially helps
distribution or bootstrap.

## Decision

Both are committed. A C build from a source checkout or tarball then needs
only a C compiler and CMake, not Python; and the GitHub Pages deployment
publishes the committed demo as it is, needing no Emscripten.

## Consequences

- Never edit them by hand; regenerate (AGENTS.md lists how).
- `tools/check_generated_data.py`, run in CI, regenerates the C tables and
  fails if they differ from the committed ones, so a committed table can never
  drift from its source.
- The WebAssembly build is not rebuilt in CI, because Emscripten versions emit
  different bytes from the same sources. Instead `web/BUILD_INFO` records a
  SHA-256 over the build's inputs, and `tools/wasm_inputs.py --check`, run in
  CI, fails when the sources no longer match it. CI also compiles the library
  to WebAssembly for a smoke test in Node and runs the committed demo's
  `app.js` against the committed module.
