# LeakSanitizer suppressions for running the wrapper tests under AddressSanitizer.
#
# CPython allocates type objects and their subclass dictionaries once and keeps
# them for the life of the process; LeakSanitizer reports the four of them at
# exit. These are the frames where that happens.
#
# Suppressing by frame rather than by library on purpose: `leak:libpython`
# would also cover every merkmal allocation, since all of them are reached
# through an interpreter frame.
#
# What this job does and does not prove. It exercises the extension's own
# refcounting and buffer handling under ASan, which is the point. It is not a
# reliable leak check: LeakSanitizer scans the stack conservatively, and a
# deliberately leaked allocation injected into the extension was classified as
# still reachable and never reported, with or without this file. Leak coverage
# for the C core comes from the ctest suite under ASan, where it does catch
# real leaks -- it caught one in the resolver during this work.
leak:_PyType_AllocNoTrack
leak:dictresize
leak:type_new
